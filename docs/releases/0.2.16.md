**Какой APK скачать:** `arm` - подходит любому телефону и ТВ (рекомендуется). `arm64-v8a` / `armeabi-v7a` - поменьше, под одну архитектуру; `universal` - для всего, включая x86.

**Плеер**
- AVI с MPEG-4 Part 2 (XviD/DivX). На Allwinner H618 первые кадры проходили, затем «Ошибка декодера». Packed bitstream кладёт B-кадр в тот же буфер, что и опорный: MediaCodec ждёт один кадр и падает. Распаковка до декодера (как `mpeg4_unpack_bframes`) это чинит: упакованный XviD играет через программный `c2.android.mpeg4`.
- Fourcc `DIV3`/`DIV4` читается как MS-MPEG4 (`video/mp43`).
- В режиме «Авто» ошибка видео посреди потока для этого MIME переключает на программный MediaCodec (`c2.android` / `OMX.google`). Другие ролики в плейлисте остаются на аппаратном декодере.
- Запасной FFmpeg включается только если `FfmpegLibrary.supportsFormat` истинно. В `libavcodec` nextlib 1.11.1-0.16.0 видео декодеры только `h264`, `hevc`, `mpegvideo`, `mpeg2video`, `vp8`, `vp9`, `libdav1d`. `mpeg4`, `msmpeg4v1-3`, `h263`, `wmv1-3`, `vc1`, `wmav1`, `wmav2`, `wmapro` не собраны: в .so есть имена из таблицы кодеков, не код декодера. Сопоставление MIME остаётся, чтобы сборка с этими декодерами заработала без правки Java.
- Если видео декодировать нечем, плеер останавливается и называет кодек (`error.decoder_codec_no_ffmpeg`). Звук без картинки и без ошибки больше не играет. Повтор декодера откладывается на следующий кадр главного потока и начинается с `stop()`, чтобы не вызывать `queueInputBuffer` у уже отпущенного MediaCodec. Предупреждение о запасном декодере на узком экране стоит ниже двух рядов кнопок.
- Размер APK не вырос. Класс `FfmpegLibrary` собран внутрь `player-core` (и в APK, и в опубликованный AAR). Вторую зависимость `nextlib-media3ext` подключать не нужно: будет две копии класса.

Библиотека: `tv.p2160:player-core:0.2.16` (versionCode 28).

**English:** AVI with MPEG-4 Part 2 (XviD/DivX) showed a few frames on an Allwinner H618 and then a decoder error. Packed B-frames share a buffer with the reference frame, which MediaCodec rejects. Unpacking before decode fixes that: packed XviD plays through the software `c2.android.mpeg4`. `DIV3`/`DIV4` is read as MS-MPEG4. In Auto, a mid-stream video decoder error retries the software MediaCodec for that MIME. FFmpeg is used only when `FfmpegLibrary.supportsFormat` is true. nextlib 1.11.1-0.16.0 `libavcodec` enables video decoders `h264`, `hevc`, `mpegvideo`, `mpeg2video`, `vp8`, `vp9` and `libdav1d` only. `mpeg4`, `msmpeg4`, `h263`, WMV and VC-1 are names in the codec table, not compiled decoders. If nothing can decode the video, playback stops with an error that names the codec. Audio does not continue alone. The APK does not grow. `FfmpegLibrary` is compiled into player-core, so a module dependency and the published AAR both carry it. Do not also add `nextlib-media3ext` or the class is duplicated. Library: `tv.p2160:player-core:0.2.16` (versionCode 28).
