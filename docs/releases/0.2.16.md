**Какой APK скачать:** `arm` - подходит любому телефону и ТВ (рекомендуется). `arm64-v8a` / `armeabi-v7a` - поменьше, под одну архитектуру; `universal` - для всего, включая x86.

**Плеер**
- AVI с MPEG-4 Part 2 (XviD/DivX). На Allwinner H618 первые кадры проходили, затем «Ошибка декодера». Packed bitstream кладёт B-кадр в тот же буфер, что и опорный: MediaCodec ждёт один кадр и падает. Распаковка до декодера (как `mpeg4_unpack_bframes`) это чинит: упакованный XviD играет через программный `c2.android.mpeg4`.
- Fourcc `DIV3`/`DIV4` читается как MS-MPEG4 (`video/mp43`).
- В режиме «Авто» ошибка видео посреди потока для этого MIME переключает на программный MediaCodec (`c2.android` / `OMX.google`). Другие ролики в плейлисте остаются на аппаратном декодере.
- Запасной FFmpeg включается только если `FfmpegLibrary.supportsFormat` истинно. В `libavcodec` nextlib 1.11.1-0.16.0 видео декодеры только `h264`, `hevc`, `mpegvideo`, `mpeg2video`, `vp8`, `vp9`, `libdav1d`. `mpeg4`, `msmpeg4v1-3`, `h263`, `wmv1-3`, `vc1`, `wmav1`, `wmav2`, `wmapro` не собраны: в .so есть имена из таблицы кодеков, не код декодера. Сопоставление MIME остаётся, чтобы сборка с этими декодерами заработала без правки Java.
- Если видео декодировать нечем, плеер останавливается и называет кодек. В «Авто» и в аппаратном режиме текст «На этом устройстве нет декодера для …». «Режим FFmpeg этот кодек не декодирует» только когда режим декодера сам FFmpeg. MPEG-4 с GMC (декодер устройства есть, но такой поток не берёт): «Декодер этого устройства не поддерживает GMC в MPEG-4 XviD/DivX». Звук без картинки и без ошибки больше не играет. Повтор декодера откладывается на следующий кадр главного потока. Предупреждение о запасном декодере на узком экране стоит ниже двух рядов кнопок.
- MP3 в AVI. Кусок контейнера часто не равен кадру MP3, и на Realtek (Android 9, `OMX.google.mp3.decoder`) звуковые часы почти стоят: `Unexpected audio track timestamp discontinuity`, картинка на 0:00. Кадры режутся по заголовку MP3, время ставится по числу сэмплов. Индекс кусков запоминает, сколько сэмплов было до каждого, и перемотка продолжает эту шкалу, а не номер куска. Индекс под замком: поток загрузки дописывает куски, поток воспроизведения ищет двоичным поиском. Повтор метки отсекает множество, а не просмотр всего списка. Кадр на границе двух кусков склеивается. Свободный битрейт и мусор остаются на метках контейнера. Если разрывы всё равно идут или 8 с нет новых кадров, на файл не больше двух попыток: одна смена звука на FFmpeg (`mp3` в libavcodec есть), затем ошибка. Пауза, стоп и перемотка этот таймер сбрасывают. Если картинки так и нет, ошибка называет кодек.
- Файл с заголовком `RIFF....AVI ` открывает только экстрактор AVI, даже если в `movi` с байта 10260 лежат четыре кадра MP3 (Eurostar и другие cab-view). Иначе Media3 сначала пробует MP3, `content://` не сообщает тип, и ролик открывается как один звук.
- Перемотка MP3. Индекс сэмплов, собранный с середины файла, больше не считает первый кусок нулевым: позиции берутся из idx1 (накопленные байты звука и битрейт strf, а если кадр уже известен, из его размера). Дальше последнего куска, который уже прочитан, точка берётся из idx1, а не читается файл подряд. Назад на отсчёте «Следующая серия» снимает отсчёт и не закрывает плеер. Карточка называется «Далее».
- MS-MPEG4. В Media3 1.11.1 нет FourCC `DIV3`/`DIV4`, поэтому дорожка не создаётся и декодер не выбирается. Заголовок `strl` читается независимо от порядка `strh`/`strf`, `DIV3`/`DIV4` становятся `video/divx3` (не `video/mp4v-es`). Список устройства пробует `OMX.realtek.video.dec.divx3`, затем `video/mp43`. `MP43` остаётся `video/mp43`. На Dune `OMX.realtek.video.dec.mp43` есть в `media_codecs`, но OMX отвечает `InvalidComponentName` ещё до `KEY_MIME` (и для `video/divx3`, и для `video/mp43`). Программного декодера этого MIME нет, FFmpeg без `msmpeg4v3`. Пустой запасной проход не запускается: иначе видео отбрасывается и остаётся один звук. В «Авто» показывается «На этом устройстве нет декодера для MS-MPEG4 DIV3» или «для MS-MPEG4 MP43», по FourCC. Фраза про режим FFmpeg только если он выбран в настройках.
- Длительность AVI. Media3 ставит `avih.dwTotalFrames * dwMicroSecPerFrame` и потом берёт максимум, поэтому верный и более короткий video `strh` (Tarkovsky: 32981 кадров при 30000/1001 = 18:20) не сокращал 43:50. Длина теперь из video `strh`, иначе из числа `##dc`/`##db` в idx1, и только потом из avih. `dwSampleSize` видео для длины не используется. Полоска не уходит дальше этого конца.
- Если в заголовке есть видео, а экстрактор дорожку не отдал, плеер показывает ошибку с FourCC, а не играет один звук.
- Сторож кадра не считает паузу, буферизацию и перемотку (в том числе короткие seek с пульта). Если во вход декодера ничего не приходит, звуковой декодер не переключается: это чтение контейнера. Кадр MP3 48 кГц (24 мс), после которого в куске нули, больше не выбрасывается.
- «Видео декодируется программно» пишется только если выбранный декодер программный. Заниженная возможность аппаратного декодера (720p) предупреждение больше не включает.
- «ЭФИР» не вспыхивает, пока файл открывается и длина ещё неизвестна. Плашка только у телеканала или когда плеер уже подтвердил живой элемент.
- После ошибки видео `flush` уже отпущенного MediaCodec не пишет `Disable failed.`
- Текст ошибки без двойных скобок: «Ошибка декодера (MPEG-4 XviD/DivX)».
- Пульт: диалог ошибки забирает фокус и не пускает OK в кнопки под ним. Назад на этом диалоге закрывает плеер, как «Закрыть», и не уводит фокус с «Повторить» и «Закрыть». Пока идёт буферизация, центральная кнопка остаётся в фокусе. Вверх с ряда воспроизведения открывает кнопку «Сведения».
- Размер APK не вырос. Класс `FfmpegLibrary` собран внутрь `player-core` (и в APK, и в опубликованный AAR). Вторую зависимость `nextlib-media3ext` подключать не нужно: будет две копии класса.
- Конец файла. Настройка «По окончании»: «Следующий» (отсчёт 5 с, Назад или «Отмена» его останавливают), «Закрыть плеер», «Остаться на кадре» (через 3 минуты кадр гаснет), «Повтор». Один файл: «Смотреть снова» и «Закрыть», фокус на «Закрыть», без нажатий закрытие через 12 с. Последний в плейлисте: «Плейлист завершён» и возврат в папку. Эфир не трогается. Досмотренный файл в следующий раз открывается с начала.
- За 15 с до конца (или на последней главе с названием вроде титров) в углу карточка «Далее» с обложкой и «Смотреть сейчас». Фокус она не забирает: вниз с пульта, если нужно нажать. Пока открыт вопрос «Продолжить с …», карточка не показывается. Назад на этом вопросе продолжает с сохранённого места. Подсказка «Продолжено с …» стоит ниже верхних кнопок и на широком экране слева от карточки «Далее». В портрете ряд иконок ужимается по ширине, правая кнопка не обрезается.
- Частично просмотренный файл при включённом «Продолжать с места остановки» спрашивает «Продолжить с …» или «С начала». Явная позиция и `from_start` по-прежнему сильнее. В списках файлов у просмотренного галочка и подпись, у недосмотренного полоска.
- «Заставка при паузе» (включена): через 3 минуты паузы кадр гаснет, любая клавиша или касание возвращает его на том же месте.
- Результат вызывающему приложению по-прежнему содержит MX `position`/`duration`/`end_by` и VLC `extra_position`/`extra_duration`. Добавлены `tv.p2160.extra.WATCHED`, `tv.p2160.extra.POSITION` и `tv.p2160.extra.DURATION` (Long, мс).

**English:** AVI with MPEG-4 Part 2 (XviD/DivX) showed a few frames on an Allwinner H618 and then a decoder error. Packed B-frames are unpacked before decode, so packed XviD plays through `c2.android.mpeg4`. `DIV3`/`DIV4` is its own MIME `video/divx3`, not MPEG-4 Part 2. FFmpeg video is used only when `supportsFormat` is true. This nextlib build does not include `mpeg4`, `msmpeg4`, `h263`, WMV or VC-1. MP3 inside AVI is timestamped from MP3 frames, because chunk timestamps stall the Realtek audio clock. If discontinuities continue, or no picture appears within 8 seconds, audio retries the FFmpeg MP3 decoder once. If nothing renders, playback stops with an error that names the codec. The software-decode warning follows the decoder that actually started. The live badge waits until the item is known to be live. A released codec no longer logs `Disable failed.` DIV3/DIV4 is exposed as video/divx3 (not MPEG-4 Part 2) and offered to the divx3 and mp43 decoders. If the device lists a component OMX will not create (`InvalidComponentName` on `OMX.realtek.video.dec.mp43`) and no software decoder exists, playback stops with the named codec error instead of dropping to audio only. A file that starts with `RIFF....AVI ` is opened only by the AVI extractor, so an AVI whose `movi` begins with MP3 frames is not sniffed as MP3. The MP3 chunk index is locked and seek uses binary search. AVI duration prefers the video strh over an inflated avih total. A declared video stream that the extractor drops is an error, not silent audio. The frame watchdog ignores pause, buffering and seeks, and does not switch the audio decoder when no video input arrives. The error dialog takes D-pad focus, and Back closes the player the same way as Close. The up-next card stays hidden while the resume prompt is open. Back on that prompt continues from the saved position. In Auto and hardware mode a missing decoder says there is no decoder for the named codec. MPEG-4 GMC instead says the device decoder does not support GMC. The FFmpeg-mode sentence is only used when that mode is selected. The resumed-from hint sits below the top buttons, and on a wide screen to the left of the up-next card. Portrait toolbar icons shrink to fit the width. Library: `tv.p2160:player-core:0.2.16` (versionCode 28).
