**Какой APK скачать:** `arm` - подходит любому телефону и ТВ (рекомендуется). `arm64-v8a` / `armeabi-v7a` - поменьше, под одну архитектуру; `universal` - для всего, включая x86.

**Плеер**
- AVI с MPEG-4 Part 2 (XviD/DivX). На Allwinner H618 первые кадры проходили, затем «Ошибка декодера». Packed bitstream кладёт B-кадр в тот же буфер, что и опорный: MediaCodec ждёт один кадр и падает. Распаковка до декодера (как `mpeg4_unpack_bframes`) это чинит: упакованный XviD играет через программный `c2.android.mpeg4`.
- Fourcc `DIV3`/`DIV4` читается как MS-MPEG4 (`video/mp43`).
- В режиме «Авто» ошибка видео посреди потока для этого MIME переключает на программный MediaCodec (`c2.android` / `OMX.google`). Другие ролики в плейлисте остаются на аппаратном декодере.
- Запасной FFmpeg включается только если `FfmpegLibrary.supportsFormat` истинно. В `libavcodec` nextlib 1.11.1-0.16.0 видео декодеры только `h264`, `hevc`, `mpegvideo`, `mpeg2video`, `vp8`, `vp9`, `libdav1d`. `mpeg4`, `msmpeg4v1-3`, `h263`, `wmv1-3`, `vc1`, `wmav1`, `wmav2`, `wmapro` не собраны: в .so есть имена из таблицы кодеков, не код декодера. Сопоставление MIME остаётся, чтобы сборка с этими декодерами заработала без правки Java.
- Если видео декодировать нечем, плеер останавливается и называет кодек (`error.decoder_codec_no_ffmpeg`). Звук без картинки и без ошибки больше не играет. Повтор декодера откладывается на следующий кадр главного потока. Предупреждение о запасном декодере на узком экране стоит ниже двух рядов кнопок.
- MP3 в AVI. Кусок контейнера часто не равен кадру MP3, и на Realtek (Android 9, `OMX.google.mp3.decoder`) звуковые часы почти стоят: `Unexpected audio track timestamp discontinuity`, картинка на 0:00. Кадры режутся по заголовку MP3, время ставится по числу сэмплов. Индекс кусков запоминает, сколько сэмплов было до каждого, и перемотка продолжает эту шкалу, а не номер куска. Кадр на границе двух кусков склеивается. Свободный битрейт и мусор остаются на метках контейнера. Если разрывы всё равно идут или 8 с нет новых кадров, на файл не больше двух попыток: одна смена звука на FFmpeg (`mp3` в libavcodec есть), затем ошибка. Пауза, стоп и перемотка этот таймер сбрасывают. Если картинки так и нет, ошибка называет кодек.
- MS-MPEG4 (`video/mp43`) сначала пробует декодеры `video/mp43`, `video/divx3`, `video/divx` и `video/x-divx`. На Dune HD это `OMX.realtek.video.dec.mp43` и `OMX.realtek.video.dec.divx3`. Нет ни одного - прежняя ошибка с именем кодека.
- «Видео декодируется программно» пишется только если выбранный декодер программный. Заниженная возможность аппаратного декодера (720p) предупреждение больше не включает.
- «ЭФИР» не вспыхивает, пока файл открывается и длина ещё неизвестна. Плашка только у телеканала или когда плеер уже подтвердил живой элемент.
- После ошибки видео `flush` уже отпущенного MediaCodec не пишет `Disable failed.`
- Текст ошибки без двойных скобок: «Ошибка декодера (MPEG-4 XviD/DivX)».
- Пульт: диалог ошибки забирает фокус и не пускает OK в кнопки под ним. Пока идёт буферизация, центральная кнопка остаётся в фокусе. Вверх с ряда воспроизведения открывает кнопку «Сведения».
- Размер APK не вырос. Класс `FfmpegLibrary` собран внутрь `player-core` (и в APK, и в опубликованный AAR). Вторую зависимость `nextlib-media3ext` подключать не нужно: будет две копии класса.

Библиотека: `tv.p2160:player-core:0.2.16` (versionCode 28).

**English:** AVI with MPEG-4 Part 2 (XviD/DivX) showed a few frames on an Allwinner H618 and then a decoder error. Packed B-frames are unpacked before decode, so packed XviD plays through `c2.android.mpeg4`. `DIV3`/`DIV4` is read as MS-MPEG4 and is offered to `video/mp43` and `video/divx3` decoders. FFmpeg video is used only when `supportsFormat` is true. This nextlib build does not include `mpeg4`, `msmpeg4`, `h263`, WMV or VC-1. MP3 inside AVI is timestamped from MP3 frames, because chunk timestamps stall the Realtek audio clock. If discontinuities continue, or no picture appears within 8 seconds, audio retries the FFmpeg MP3 decoder once. If nothing renders, playback stops with an error that names the codec. The software-decode warning follows the decoder that actually started. The live badge waits until the item is known to be live. A released codec no longer logs `Disable failed.` The error dialog takes D-pad focus. Library: `tv.p2160:player-core:0.2.16` (versionCode 28).
