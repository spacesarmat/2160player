**Какой APK скачать:** `arm` - подходит любому телефону и ТВ (рекомендуется). `arm64-v8a` / `armeabi-v7a` - поменьше, под одну архитектуру; `universal` - для всего, включая x86.

**Плеер**
- AVI с WMV и VC-1. Fourcc `WMV3`, `WVC1`, `WMV1`, `WMV2` больше не выбрасываются. `WVC1` идёт как `video/wvc1` (декодер `vc1`), `WMV3` как `video/x-ms-wmv` (`wmv3`), `WMV1` и `WMV2` как `video/wmv1` и `video/wmv2`: один MIME не выбирает три разных декодера FFmpeg.
- Хвост BITMAPINFOHEADER (для WMV3 это обычно 4 байта заголовка последовательности) передаётся в `initializationData`. Без него декодер WMV3/VC-1 не стартует.
- Эти декодеры уже были в `libavcodec` на всех ABI (`wmv1`, `wmv2`, `wmv3`, `vc1`, а также `wmav1`/`wmav2`). Новая сборка FFmpeg не добавлялась, размер APK не вырос. Если у устройства есть MediaCodec на `video/wvc1`, режим «Авто» пробует его первым, иначе сразу FFmpeg.
- Контейнер ASF (файлы `.wmv`) по-прежнему не читается: у Media3 нет демуксера ASF. Минимальный разбор (видео WMV + звук WMA, в том числе сжатые пакеты) - это отдельный экстрактор на несколько сотен строк и всё равно ломается на типичных файлах. В этот выпуск он не входил.

Библиотека: `tv.p2160:player-core:0.2.17` (versionCode 29).

**English:** AVI files with WMV and VC-1 are recognized. `WVC1` is `video/wvc1` (FFmpeg `vc1`), `WMV3` is `video/x-ms-wmv` (`wmv3`), and `WMV1`/`WMV2` are `video/wmv1` and `video/wmv2`, because one MIME cannot select three decoders. The BITMAPINFOHEADER tail is passed as initialization data. Those decoders were already in `libavcodec` on every ABI, so the APK does not grow. A device MediaCodec for `video/wvc1` is tried first in Auto. ASF (`.wmv`) is still not demuxed: a minimal demuxer is a few hundred lines and still fails on common compressed packets, so it is not in this release. Library: `tv.p2160:player-core:0.2.17` (versionCode 29).
