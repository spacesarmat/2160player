**Какой APK скачать:** `arm` — подходит любому телефону и ТВ (рекомендуется). `arm64-v8a` / `armeabi-v7a` — поменьше, под одну архитектуру; `universal` — для всего, включая x86.

**Защита трансляции и сопряжения**
- RTSP больше не пускает зрителя одним `SETUP` без пароля. `DESCRIBE` и `SETUP` требуют Basic, если защита включена. `PLAY`, пауза и отключение — только после успешного `SETUP` на том же соединении.
- Пароль потока — новый на каждую трансляцию и не совпадает с кодом сопряжения. Сопряжённый 2160 Player по-прежнему берёт адрес с паролем сам (`GET /camera`). VLC и OBS копируют пароль с экрана телефона: старый приём «ввести код передачи» больше не подходит. Защита «выключена» оставляет поток без пароля.
- QR-ссылка «смотреть трансляцию» живёт 15 минут и использует отдельный ключ, не PIN и не пароль RTSP. Уже открытая страница показывает адрес с паролем сеанса.
- Новый свой код сопряжения — 6–8 цифр. Уже сохранённый код из 4–5 цифр работает, пока его не сменят. Уже выданные сопряжения не сбрасываются.
- На ТВ и в диалоге входящего просмотра по умолчанию выбрано «Отклонить» / «Отмена», на экране виден код для сверки.
- Слишком частые запросы на сопряжение с одного адреса отклоняются. Токен после «Разрешить» получает только тот адрес, который прислал запрос.
- Серверы передачи и RTSP слушают только частные адреса локальной сети, не все адреса интерфейса.
- При выключенной защите чужие заголовки `Authorization` и `Cookie` в «что сейчас играет» не передаются. Сопряжённым устройствам при включённой защите — передаются.
- Первый выбор «защита выключена» спрашивает подтверждение.
- Пароли SMB и ключ RTMP при запуске переносятся в шифрованное хранилище, открытый текст стирается. Эти настройки, сопряжения и кэш IPTV не попадают в резервную копию. Трафик в локальной сети по-прежнему HTTP.

**English:** RTSP now requires Basic auth on DESCRIBE and SETUP when protection is on, and PLAY/PAUSE/TEARDOWN only after a successful SETUP on the same connection. The stream password is random per session and is not the pairing PIN: paired 2160 Players still receive it from GET /camera, while VLC and OBS must copy it from the phone screen. Protection off stays passwordless. The QR /watch link uses a separate key that lasts 15 minutes. New custom PINs are 6–8 digits; a saved 4–5 digit PIN still works until changed, and existing pairings stay valid. The TV pairing dialog and the incoming-playback dialog focus Reject/Cancel and show the code. Pairing challenges are rate-limited per IP, and the token is released only to the IP that asked. Handoff and RTSP bind private LAN addresses only. With protection off, /now omits Authorization and Cookie. Turning protection off asks once. SMB passwords and the RTMP key move to encrypted storage at startup, and those preferences plus the IPTV cache are excluded from backup. LAN traffic stays HTTP.
