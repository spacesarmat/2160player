# HTTP API

У плеера нет облачного backend. HTTP есть в двух местах: сервер на самом устройстве и запросы
приложения к GitHub Releases.

Сервер поднимает `Handoff`, пока приложение на экране или идёт трансляция камеры. Порт случайный,
mDNS — `_p2160._tcp`. Чужой интерфейс (не локальная сеть) получает обрыв без тела ответа.
Тело POST читается не больше 64 КБ. Ошибок TLS нет: трафик в сети не шифруется.

Заголовок сопряжения: `X-P2160-Token: <32 hex>`. Без действующего токена и при включённой защите
`/now`, `/play` и `/camera` отвечают `401` с пустым телом.

## Устройство: сопряжение

### `GET /pair/challenge?id=&name=`

Новый запрос. `name` обрезается до 64 символов.

- `200` `{"nonce":"<hex>"}` — у хозяина уведомление «Разрешить / Отклонить». Живёт 3 минуты.
- `403` пустое тело — этот `id` отклоняли меньше 10 минут назад, уведомления нет.

### `GET /pair/status?nonce=`

Клиент опрашивает примерно раз в 1,5 с.

- `200` `{"state":"pending"}` | `{"state":"approved","token":"…"}` | `{"state":"denied"}`.
  Токен после `approved` отдаётся один раз, затем запрос закрывается.
- `404` — нет такого nonce, истёк или уже закрыт.

### `POST /pair`

```json
{ "id": "client", "name": "Телефон", "nonce": "…", "proof": "<hex HMAC-SHA256>" }
```

`proof = hex(HMAC-SHA256(код, "<nonce>:<id>"))`. Код — 6 цифр до полуночи или свой из 4–8 цифр.

- `200` `{"token":"…"}`
- `403` — неверный код, запрос остаётся открытым
- `429` — 5 ошибок подряд, пауза 1 минута
- `400` — nonce неизвестен, просрочен, отклонён или от другого `id`

## Устройство: присутствие и просмотр

### `GET /hello?id=&name=&port=&auth=&cam=`

`id` и `port` обязательны, `id` не равен себе. `auth=1` — у соседа включена защита, `cam=1` — у него RTSP-камера.

- `204` пустое тело — сосед добавлен в список. Если он нас ещё не знал, уходит ответный hello.
- `400` — нет id, свой id или порт не число.

### `GET /now`

- `401` — нет токена
- `204` — ничего не играет или схему нельзя отдать (`torrent://` и прочее)
- `200` JSON:

```json
{
  "uri": "smb://nas/Movies/Film.mkv",
  "title": "Фильм",
  "position": 764000,
  "duration": 7200000,
  "playing": true,
  "headers": { "User-Agent": "…" }
}
```

Локальный `file`/`content` подменяется на `http://<ipv4>:<port>/stream/<token>/<имя>`, заголовки очищаются.
`smb`, `http`, `https`, `rtsp` передаются как есть.

### `POST /play`

Тело — тот же JSON плюс `"from": "имя отправителя"`. Ответ `200` `{}` сразу, затем диалог
«продолжить здесь». Согласие запускает плеер с той же позиции. `401` без токена. Битый JSON — обрыв
соединения (исключение на сервере), отдельного кода нет.

### `GET /camera`

- `401` без токена
- `204` — RTSP-трансляции нет
- `200` `{"url":"rtsp://…","viewers":0}` — в `url` уже логин и пароль, если защита включена

### `GET /watch?k=<код>`

HTML-страница для QR-кода камеры. Код `k` нужен, только если защита передачи не выключена.

- `200` `text/html` — кнопки `intent://…#Intent;scheme=rtsp;package=tv.p2160.player;…;end`, запасная
  ссылка на APK и адрес RTSP
- `403` — неверный код
- `429` — 5 неверных подряд, минута ожидания
- `404` — сейчас нет RTSP-трансляции

Текст страницы экранируется. Пароль RTSP в адресе есть: страница для того, кто сканирует QR у телефона.

### `GET /stream/<token>/<имя>`

Файл, выданный в `/now` или при отправке. Токен — ключ в памяти процесса, после перезапуска пропадает.

- `200` — файл целиком, `Accept-Ranges: bytes`
- `206` — заголовок `Range: bytes=start-end`, `bytes=start-` или `bytes=-suffix`.
  Суффикс длиннее файла отдаёт файл с нуля. `Content-Range: bytes start-end/size`
- `404` — нет токена
- `416` — диапазон невыполним (`start` за концом, `end < start`, `Range` на пустом файле).
  Тело пустое, `Content-Range: bytes */size`, `Content-Length: 0`

Нечисловой диапазон тоже `416`, а не обрыв соединения.

### `GET /app` и `GET /app/<имя файла>`

APK «Поделиться приложением». Без кода: это само приложение, не просмотр.
`200` или `206`, `Content-Type: application/vnd.android.package-archive`,
`Content-Disposition: attachment`. Тот же разбор `Range`, что у `/stream`.

Адрес для QR: `http://<ipv4>:<port>/app/2160player-<version>.apk`.

Неизвестный путь — `404` с пустым телом.

## GitHub Releases (исходящие)

База: `https://api.github.com/repos/spacesarmat/2160player`.
Заголовок `Accept: application/vnd.github+json`, `User-Agent: 2160Player/<версия>`.
Тайм-ауты: соединение 15 с, чтение 30 с. Код вне 200–299 — ошибка `HTTP <код>`, соединение закрывается.

| Запрос | Кто вызывает | Успех | Ошибка |
|---|---|---|---|
| `GET /releases/latest` | проверка обновления | релиз новее установленного: версия из `tag_name` без `v`, текст `body`, URL и размер APK | нет более новой версии — «у вас последняя»; нет подходящего APK — `no APK in release` |
| `GET /releases/tags/v<version>` | «Поделиться», если стоит APK одной архитектуры | asset с `-arm-` в имени, иначе `universal` | `no shared APK` |

Выбор APK: на ARM сначала имя с `-arm-`, иначе `-<abi>-` по `Build.SUPPORTED_ABIS`, иначе `universal`.
Скачивание — `GET` по `browser_download_url` в `cacheDir/update`. Отладочный пакет
(`tv.p2160.player.debug`) APK не ставит: открывается `html_url` релиза в браузере.

Состояния `Updater.state`: `Idle`, `Checking`, `UpToDate`, `Available`, `Downloading`, `Installing`, `Failed(message)`.
