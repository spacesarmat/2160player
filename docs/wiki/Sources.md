# Источники

Плеер открывает URI из `PlaybackRequest`. Схема выбирает источник.

| Схема | Модуль | Примечание |
|---|---|---|
| `file`, `content` | Media3 | локальные файлы и SAF. Обзор на ТВ - `LocalBrowserScreen` |
| `http`, `https` | Media3 | cleartext HTTP разрешён. Заголовки запроса - `PlaybackRequest.headers` |
| `rtsp`, `rtsps` | Media3 RTSP по TCP | низкая задержка, если все элементы плейлиста живые |
| `udp`, `rtp` | низкая задержка | MPEG-TS. Схема `srt` тоже включает этот режим буфера, но отдельного проигрывателя SRT нет: SRT в приложении - исходящая трансляция камеры |
| `smb` | smbj, SMB 2/3 | см. ниже |
| `torrent` | `source-torrent` | просмотр, пока качается |

HLS/DASH/SmoothStreaming определяются по MIME (`application/x-mpegURL`, `application/dash+xml`,
`application/vnd.ms-sstr+xml`) или по `.m3u8` в URL.

## Субтитры рядом с файлом

SRT, ASS/SSA, VTT и TTML. Плеер сам берёт `Movie.srt` и `Movie.ru.srt` рядом с `Movie.mkv` (`Movie2.srt` не подходит).

- `file://` и `smb://` - каталог читается сразу.
- `content://` (системный выбор или чужой `VIEW`): если идентификатор документа - путь на томе (`primary:Download/Movie.mp4`) и каталог доступен, то же самое, без вопроса. Иначе используется уже выданное дерево SAF на эту папку. Если его нет, плеер один раз просит открыть папку (на Android 8 и новее выбор сразу стоит на родительской). Разрешение сохраняется. Отказ или другая папка запоминаются, при следующем открытии вопрос не повторяется. На Android TV это системный экран DocumentsUI, пульт его ведёт.

«Загрузить из файла…» принимает тот же набор, в том числе `content://` (DocumentsUI часто отдаёт `application/octet-stream`). Дорожка включается сразу. Файл запоминается для этого видео и подключается снова при следующем открытии. Текст приводится к UTF-8. Поле `charset` в `TEXT_TRACKS` задаёт кодировку явно, иначе остаётся автоопределение, включая cp1251.

## Озвучка рядом с файлом

`.mka`, `.ac3`, `.eac3`, `.ec3`, `.dts`, `.aac`, `.m4a`, `.mp3`, `.flac`, `.opus`, `.ogg`, `.wav`. Имя начинается так же, как у видео (`Movie.ru.mka` к `Movie.mkv`). Папка `Audio`, `Sound`, `RUS Sound` и похожие просматривается на один уровень.

`file://` и SMB читают каталог. `content://` берёт тот же путь документа и то же дерево папки, что и субтитры, и ещё папку озвучки на один уровень. Пустой путь на диске не прячет файлы, которые видит дерево. HTTP без query пробует каталог или короткий список имён. HTTP с query (TorrServer) соседей не ищет: дорожки передают в `tv.p2160.extra.AUDIO_TRACKS`.

«Загрузить из файла…» в панели звука включает файл сразу и запоминает его. Переключение не начинает видео заново. Если файл не открылся или кодек не поддерживается, видео продолжает играть. Авто/FFmpeg и passthrough на ресивер относятся и к этой дорожке, когда формат позволяет.

## SMB

`smb://хост/шара/путь`. Логин и пароль - в сохранённых серверах (`SmbServers`), не в URI.
Нет шары в доступе - пустой список, не исключение наружу у обзора. Ошибка открытия файла в плеере -
«нет доступа» или «не найдено» (`error.no_permission` / `error.not_found`).

Поиск в локальной сети (mDNS) подставляет в адрес IPv4, затем имя хоста или `<имя>.local`. Link-local IPv6 (`fe80::…%wlan0`) в поле адреса не попадает.

Публично: `SmbServers`, `SmbConnections` (список шары и каталога). Подробности - [API.md §11](../API.md#11-smb).

## DLNA

SSDP и описание устройства, затем SOAP `ContentDirectory:Browse`.

- Управление: `DlnaServers`, `ContentDirectory.browse` / `browseAll`.
- Ошибка SOAP (часто HTTP 500) - `DlnaException` с кодом UPnP (`701` - нет объекта).
- Воспроизведение - HTTP URL из DIDL, не сам DLNA-поток. Субтитры рядом подхватываются как внешние.
- `childCount` 0 или отсутствие числа - сервер не знает, сколько внутри (так делает MiniDLNA). В списке это не «Объектов: 0». Число «3» у папки Video - её виртуальные разделы (All Video, Folders, …), а не три файла. Пустой All Video - пустой ответ сервера.
- На корне каталога имя сервера только в заголовке, без второй такой же строки.

[API.md §19](../API.md#19-dlnaupnp).

## IPTV

`M3uParser.parse(text, baseUrl)` → каналы, группы, EPG URL из шапки, заголовки потока.
Мусор и HTML не становятся каналами: строка без URL дописывается к названию.
`XmltvParser` читает XMLTV (и gzip), окно по умолчанию −6 ч…+24 ч. Время без пояса - UTC.
`IptvStore` кэширует плейлист; ошибка сети оставляет старый кэш и пишет текст в `IptvPlaylist.error`.

Режим эфира - `PlaybackRequest.liveTv` или `tv.p2160.extra.LIVE`. [API.md §20](../API.md#20-iptv-m3u-xmltv-режим-эфира).

## Торренты

`torrent://<infohash>` после `TorrentEngine`. Пока кусков нет, плеер ждёт; приоритет кусков -
окно впереди позиции, заголовок и хвост контейнера. Озвучка и субтитры из того же торрента
подключаются сами: та же серия (`S01E01` не цепляет `S01E10`), папки `RUS Sound/<студия>`,
`Audio`, `Sound`, `Rus Subs`, `Subs`, в том числе `RUS Subs [Shift]`. Дорожка торрента не
отбрасывается до первой попытки чтения. Студия берётся из папки, язык из имени. Выбор студии
сохраняется на следующую серию плейлиста. `Bonus`, `Extras`, `Sample`, `Trailer` и `Menu` не
считаются сериями. После закрытия плеера закачка останавливается примерно через 15 с, если
раздачу не включили вручную. Остановка и лимиты - `TorrentSettings`
(сеть, сидирование, только зарядка, лимит по мобильной сети).

Интеграционный тест с сетью не входит в обычный прогон: `P2160_TORRENT_IT=1`.
[API.md §21](../API.md#21-торренты-модуль-source-torrent).

## Blu-ray

Файл `.iso` или папка `BDMV` (файл, SMB, HTTP для ISO). Открывается основной фильм, главы из MPLS.
Свой экстрактор 192-байтных пакетов: TrueHD, LPCM, DTS-HD, PGS. [API.md §14](../API.md#14-blu-ray-iso-и-bdmv).

## Камера и экран телефона

Это не источник библиотеки, а сервер приложения.

- RTSP: `rtsp://<ip>:8554/`, логин `2160`, пароль - случайный на эту трансляцию (не код сопряжения), если защита включена. `DESCRIBE` и `SETUP` требуют Basic, `PLAY` - только после `SETUP` на том же соединении. Сопряжённый плеер берёт адрес с паролем из `GET /camera`.
- SRT и RTMP - телефон сам подключается к адресу из настроек.
- NDI - только если SDK был на машине сборки. Пока идёт только NDI, H.264 не кодируется: кадр уходит в NDI как RGBX. У NDI нет пароля: предупреждение, что поток виден всем в этой сети Wi-Fi, показывается только когда выбрана цель NDI.
- Камеры в ряду «Камера»: одна на сторону - «Задняя» / «Фронтальная». Несколько задних - «Основная», «Сверхширокая», «Телевик 3×». Вторая фронтальная с тем же сенсором не показывается (на S21 Ultra это кадрирование единственной фронтальной, не телевик). «Телевик» у фронтальной - только при ≥ 2× и другом сенсоре, иначе «Фронтальная (кадрирование)». Та же строка в `contentDescription`.
- «Минимальная задержка» (выключена по умолчанию) сокращает очередь отправки и буфер SRT. На слабой сети кадры тогда пропадают чаще. Ключи низкой задержки кодека включены всегда. Строка - видимый `Switch` (не текст «Вкл.» / «Выкл.»): TalkBack объявляет роль и «включено/выключено» (`checkable`). Так же фонарик, звук микрофона, переключатели настроек и ночной звук в панели плеера.
- Зум и усиление микрофона - круглый ползунок и подпись `1,0×` без разрядки букв.
- Зрители в другой копии плеера видят камеру на главном экране (`cam=1` в hello и mDNS).

Трансляция не уходит в мобильный интернет: только локальная сеть. Экран трансляции не использует
настройку «не выключать экран во время просмотра» - она про плеер, который смотрит ролик.
Страница для QR - `GET /watch` в [HTTP API](Http-API.md).
